# M9: i18n/RTL and product polish, implementation spec

**Base branch:** `parity/m9-polish`, cut from `main` at `125a432` (M0–M8 merged, #16–#26). Migrations exist up to **029** (024 M7 bot, 025–026 M6 search/ask, 027–029 M8 integrations). M9 adds **030** and nothing else.

**Shape:**
- **Step 0** (orchestrator) commits migration 030, the dependencies, the pt/es/it removal (a type-level change that would otherwise break every package), the i18n plumbing, the frozen contracts, the real shared primitives (`ConfirmDialog`, `PromptDialog`, `shell-url`, minimal `format`/`hebrew-text`), no-op stubs with their call sites, route stubs behind their final guards, the scanners and ratchet baselines, and the fail-closed visibility fix. The build stays green; behaviour changes only for locales.
- **Four parallel packages, A–D,** with strictly disjoint file ownership. A cross-cutting sweep can't be split by rule, so it is split by file: **every package removes hardcoded strings, physical CSS and `check.mjs` violations in the files it owns**, and nobody else touches those files.
  - **A:** i18n core and the string sweep over content and settings surfaces, locale detection, the Settings shell, user preferences.
  - **B:** Hebrew PDF, exports and filenames, self-hosted fonts, the share page and share dialog, the carried-over M4 items.
  - **C:** notifications bell, workspace analytics dashboard, onboarding wizard, the M9 browser e2e and screenshot matrix.
  - **D:** shell URL routing, dialogs, `loading`/`error`/`not-found`, PWA and the offline recorder, the bundle diet.
- The **Integration step** flips every ratchet to strict (0), runs the e2e in he and en, verifies the Hebrew PDF by opening it, and records evidence in STATUS.

**Goal:** a Hebrew-first UI that is visibly better than Fireflies (complete he/en, RTL-correct everywhere, Hebrew PDF), plus the parity polish still open: workspace analytics, notifications, onboarding, PWA recorder, routing, dialogs and segment states.

**UI languages: Hebrew and English only** (user decision, 2026-10-13). pt/es/it are removed, not completed.

**Design rules:** design-system README §7–10:
- set `dir` from the language you know; `dir="auto"` only for user input of unknown language;
- `<bdi>` around names, emails, titles and product names;
- LTR-isolated mono timecodes; time axes never mirror;
- iris only on AI content; one primary action per view; status pills only for exceptions;
- logical CSS only.

## Decisions (normative)
### Locales
- **`SUPPORTED_LOCALES = ["he","en"]`, default `he`** (`MEETSUM_DEFAULT_LOCALE`, `he` or `en`). `LEGACY_LOCALES = ["pt","es","it"]`: the proxy sends these URL prefixes a 308 to the resolved locale with the rest of the path kept; a legacy cookie value is ignored; stored `defaultLocale` settings of pt/es/it are coerced to `he` on read, and 030 rewrites them.
- **Resolution order:** URL prefix → cookie `meetsum_locale` → `users.locale` (signed-in) → Accept-Language (q-sorted; `he`, `he-*`, `iw` → `he`; `en-*` → `en`; `*` and malformed entries ignored) → default. Applied to **every** locale-less path, not just `/`. Redirects carry `Vary: Accept-Language, Cookie`.
- The OAuth callback sets the cookie from `users.locale` when present. Switching language persists `users.locale` when there is a session (the cookie route stays public for the login page).
- The meeting/content language (`ContentLanguage`: en/he/pt/es/it/mixed) is a separate concept and keeps all values; `meetingLanguageMode` becomes `"auto" | ContentLanguage`.

### Time zone and formatting
- **Time zone, in order:** `users.time_zone` → `workspace_settings.timeZone` → `MEETSUM_DEFAULT_TIMEZONE` (existing) → `Asia/Jerusalem`, validated with `Intl.supportedValuesOf("timeZone")`. `getTaskTimeZone()` (M5) becomes a thin wrapper over the same resolver.
- The server resolves locale, dir and zone once per request (`getRequestI18n()`) and passes them to `I18nProvider`.
- **`lib/i18n/format.ts` is the only module allowed to call `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.RelativeTimeFormat` or `toLocale*String`** (new `check.mjs` rule `locale-format`; allowlist: `format.ts`, `lib/tasks/due-date.ts` parsing, `components/ui/calendar.tsx`). Every formatter requires an explicit `timeZone` (the type enforces it). Western digits (`numberingSystem: "latn"`), `calendar: "gregory"`, `he` uses `hourCycle: "h23"`.
- Relative times render the absolute value on the server and switch to relative after mount (`useNow()`, inside `<time dateTime>`), so hydration never mismatches.

### Hebrew typography
- Applied at render and export time, **never persisted**. Stored text, search offsets, copy/clipboard and transcript segment DOM stay raw. It applies to titles, summaries, labels, dictionary strings, notifications, PDF, DOCX, email and Slack.
- `lib/i18n/hebrew-text.ts` is canonical; M8's `lib/integrations/bidi.ts` re-exports its primitives (same names, same behaviour).
- **Hebrew copy style** (`docs/i18n/hebrew-style.md`, enforced by the dictionary lint test): plural imperative (העלו, הזמינו), never a gendered singular; sentences built around the object, not a gendered actor verb ("אזכור חדש מ־<bdi>דנה</bdi>", not "דנה הזכירה"); ״ and ׳, never ASCII `"`/`'` between Hebrew letters; "…" not `...`; glossary: פגישה, תמליל, סיכום, משימה, חדר, סביבת עבודה, הקלטה, דובר.

### PDF
- **pdfkit + bidi-js with embedded IBM Plex Sans Hebrew, Plex Sans and Plex Mono** (OFL). Why not `@react-pdf/renderer`: it adds a React reconciler and yoga-wasm to a route handler, uses its own pdfkit fork anyway, doesn't apply full UAX #9 to mixed-direction lines, and gives no grapheme-safe reordering control. Why pdfkit: fontkit shaping (GPOS mark positioning for niqqud, kerning), subsetted fonts with a ToUnicode CMap (Hebrew stays copyable and searchable), `lang` and tagged-PDF support.
- Lines wrap in **logical** order with an injected measurer, then each line is reordered **visually** with bidi-js, reversing by grapheme cluster (`Intl.Segmenter`) so combining marks stay attached, with bracket mirroring.
- Requires `serverExternalPackages: ["pdfkit"]` (pdfkit reads AFM files via `__dirname`).
- Noto Sans Hebrew was considered; Plex Sans Hebrew is chosen because it is the UI face (Cadence) and covers Hebrew with niqqud. Glyphs outside Hebrew/Latin/Mono (Arabic, CJK, emoji) render as U+25A1 and are counted.

### Fonts: self-host in M9 (not M10)
- The PDF needs the Plex TTF files on disk anyway, so M9 vendors one font source and serves both from it: `next/font/local` (woff2) for the UI and TTF for pdfkit. This removes the only network fetch from `next build` (the CI flake) without a second font migration in M10.
- Source: the `@ibm/plex-sans-hebrew`, `@ibm/plex-sans`, `@ibm/plex-mono` npm packages if Step 0 confirms they ship `fonts/complete/{ttf,woff2}`; otherwise vendor the needed weights from the IBM Plex release into `assets/fonts/` with `OFL.txt`. Weights: Sans and Sans Hebrew 400/500/600/700, Mono 400/500 (as today). `MEETSUM_PDF_FONT_DIR` overrides the PDF font location.
- `lib/fonts.ts` keeps its exports (`plexSans`, `plexHebrew`, `plexMono`, `fontVariables`), CSS variable names and `adjustFontFallback` choices, so `tokens.css` and the layouts don't change.

### Filenames
`lib/http/content-disposition.ts` (M8) stays the only helper. M9 hardens it: NFC; strip bidi and C0/C1 controls; replace `<>:"/\|?*` with `-`; collapse whitespace; trim trailing dots and spaces; prefix Windows reserved names with `_`; cap at 120 code points without splitting a surrogate pair; extension after the cap. The ASCII fallback becomes `meetsum-<yyyy-mm-dd>-<id8>.<ext>` whenever the title has fewer than 3 ASCII letters (the signature gains an optional `{ date, id }`).

### Shell URL is the single source of truth
- `?panel=<MainPanelKey>&meeting=<id>&tab=summary|transcript|ask&t=<sec>&adminTab=<…>&section=<settingsSection>`; default values are omitted. `section` keeps M8's `?panel=settings&section=integrations` working.
- Panel and meeting changes use `router.push` (history entries); `tab` and `t` changes use `router.replace`.
- State is derived from `useSearchParams()`; there is no mirrored `useState`. The server page parses `searchParams` and renders the right panel and meeting on first paint, including a meeting outside the first page (fetched server-side through the normal visibility check); the `deepLinkedMeetingRef` hack is deleted.
- Unknown parameters (`integration_error`, `q`, `source`, `record`) are preserved.
- Separate routes stay separate: `/[locale]/tasks`, `/[locale]/search`, `/[locale]/rooms/[id]`, and the new `/[locale]/analytics` and `/[locale]/onboarding`.

### Dialogs
- `components/ui/confirm-dialog.tsx` (promoted from `components/admin/confirm-dialog.tsx`, which becomes a re-export) and `components/ui/prompt-dialog.tsx` (`usePromptDialog()` → `Promise<string | null>`, with validation and an `aria-describedby` error), both on the shadcn Dialog/AlertDialog. Focus goes to the first meaningful control; Esc and close return focus to the opener.
- New `check.mjs` rules: `window-dialog` (`window.prompt|confirm|alert`) and `hand-built-modal` (`fixed inset-0` outside `components/ui/**`).

### Notifications
- Pull-based, polled, and rendered client-side from the dictionary by kind; the server stores ids and short snapshots only (never comment text, summaries or titles in `payload`).
- Visibility is re-checked at read time: a meeting the user can no longer see gets its title blanked and its link removed.
- No email digest or push (out of scope).

### Analytics
- **Aggregates only meetings visible to the requester**, by putting `meetingScopeSql(scope, "m", values)` in the base CTE that every other statement joins to. Admins get no bypass: another member's private meeting is excluded from every number, including totals.
- The per-member talk-time breakdown is owner/admin only; members see workspace totals and their own numbers. Members with fewer than 3 visible meetings in range are folded into "others" in the breakdown.
- API keys are refused (403 `user_required`): the dashboard is for people.

### Bundle budget
- `/[locale]` First Load JS: **≤ 300 KB gzipped** after M9 (from 408.7 KB), enforced in CI by `npm run bundle:check` against `bundle-budget.json`. New routes: `/[locale]/analytics` ≤ 330 KB (recharts lives only there), `/[locale]/onboarding` ≤ 260 KB, `/share/[token]` ≤ 220 KB.
- The ratchet fails when a route exceeds its budget or grows more than 5 KB over the recorded baseline; lowering the baseline is always allowed.
- Rule: client components never import the runtime `dictionaries` object; they receive the dictionary (or a module slice) as props or from `useI18n()`.

## Hebrew typography API (`lib/i18n/hebrew-text.ts`; Step 0 minimal, A full)
```ts
export const RLM="\u200F", LRM="\u200E", WJ="\u2060", NBSP="\u00A0", LRI="\u2066", RLI="\u2067", FSI="\u2068", PDI="\u2069"
export function hasHebrew(s: string): boolean
export function firstStrongDirection(s: string): "rtl"|"ltr"|"neutral"
export function isRtlLanguage(lang?: string|null): boolean          // he, iw, he-*, yi, ar, fa
export function directionFor(lang?: string|null, text?: string): "rtl"|"ltr"   // known lang first, else first strong
export function fixHebrewTypography(s: string, opts?: { base?: "rtl"|"ltr" }): string  // idempotent; no-op without Hebrew
export function isolateLtr(s: string): string                       // LRI…PDI; plain-text outputs only (PDF/DOCX/email/Slack), never DOM
export function rtlLine(s: string): string                           // RLM prefix if first strong is LTR
export function stripBidiControls(s: string): string                 // U+200E/F, 202A–202E, 2066–2069, 061C, 2060
export function hebrewList(items: string[], locale: "he"|"en", type?: "conjunction"|"disjunction"): string
```
`fixHebrewTypography` rules, in order:
1. Tokenize and protect URLs, emails, `@mentions`, `` `code` `` spans and existing control characters.
2. **RLM after a Latin word before digits:** a Latin token (`[A-Za-z][A-Za-z0-9.+#&'’-]*`) followed by whitespace and a digit, in a string with Hebrew or an RTL base, gets `RLM` after the token ("פגישה עם Lisboa 12 משתתפים" no longer renders as "12 Lisboa").
3. **Word-joiner after prefix hyphens:** `(^|[\s(\["'׳״])([ובכלמשה]{1,3})([-־])(?=[A-Za-z0-9])` gets `WJ` after the hyphen, so "ל-Google" and "ב-14:30" never break.
4. **No-break space before a dash:** `" — "` and `" – "` become `NBSP + dash + " "`.
5. Never insert a control character next to an existing one; running it twice equals running it once.

`hebrewList`: if the last item starts with a non-Hebrew character the conjunction becomes "ו-"+WJ ("Slack, Notion ו-HubSpot"); otherwise `Intl.ListFormat` output ("א, ב וג").

## Formatting API (`lib/i18n/format.ts`; Step 0 minimal, A full)
```ts
type Fmt = { locale: "he"|"en"; timeZone: string }
formatDate(v, fmt, style: "date"|"dateShort"|"dateTime"|"time"|"weekdayDate"|"monthYear")
formatRelative(v, now: Date, fmt)     // he: "עכשיו", "לפני דקה", "לפני 5 דקות", "לפני שעתיים", "אתמול ב־14:30", "יום שלישי ב־09:00" (<7d), else "13 באוק׳ 2026"
formatDuration(ms, fmt, style: "long"|"short"|"clock")  // he long with dual forms: דקה / שתי דקות / 5 דקות; שעה / שעתיים / 3 שעות; "שעה ו־20 דקות"; en "1 hr 20 min"; clock "1:02:03"
formatNumber(n, fmt, opts?) ; formatPercent(r, fmt) ; formatCount(n, fmt, forms: {one, two?, other})   // Intl.PluralRules("he") one/two/other
formatTimecode(ms)                     // "12:34" / "1:02:03", Western digits
```
The dictionary gets plural support: `t.plural("meetingsCount", n)` looks up `<key>_one|_two|_other` and falls back to `_other`. `formatMessage` keeps `{name}` placeholders.

## Security checks (each needs a test; reviewers verify)
1. **Dashboard visibility.** Every analytics statement joins the `visible` CTE built from `meetingScopeSql`; no statement reads `meetings`, `meeting_analytics`, `action_items` or `meeting_tags` without that join (a static SQL test parses the module). Fixture: W1 admin + member, the member's private meeting with 2 h of talk time and 5 action items → the admin's totals, series, talk time, topics and action items exclude it; a cross-workspace `roomId` → 404; API keys → 403.
2. **Service worker never stores private data.** `classifyRequest` table test plus `tests/sw-private-data.test.ts`, which runs the built SW source in a fake `CacheStorage` and replays `/api/meetings`, `/api/notifications`, a navigation to `/he?meeting=…`, `/share/<token>`, a response with `Set-Cookie`, and a `no-store` response: the cache holds only `/_next/static/**`, `offline.html` and icons. Logout clears all caches. The e2e checks `caches.keys()` contents after a browsing session.
3. **Offline queue privacy.** IDB is keyed by user id; logout offers to finish or discard pending uploads and then clears; recovered recordings show only for the user who made them.
4. **Notifications.** Recipients pass `canViewMeeting` at enqueue; DTOs re-check visibility at read; payloads hold ids only; cross-workspace reads return nothing except `invited` for the matching email.
5. **Share passwords.** scrypt with salt, timing-safe verify, length limits, rate-limited verify (existing), never logged or audited; changing or clearing invalidates access cookies.
6. **Error pages** never render `error.message` or stack traces in production; the API error mapper never shows server English in `he` and never echoes request data.
7. **Fail-closed visibility** for platform events and read paths (Step 0 tests).
8. **Locale input.** Cookie, header and `?lang=` values are allowlisted (`he`/`en`); `returnTo` keeps going through `safeReturnTo` after locale redirects; time zones are validated against `Intl.supportedValuesOf`.
9. **Seed and screenshot scripts** refuse non-localhost databases and base URLs and never print cookies or secrets.

## Defaults and open questions (flag in the PR)
- **pt/es/it are removed** (user decision); restoring one later means a complete module plus the parity test. Stored pt/es/it UI preferences become `he`; meeting content languages are untouched.
- **Default locale `he`** for every locale-less request without a cookie, user preference or matching Accept-Language (an English-only browser still gets `en`).
- **Fonts are self-hosted in M9** (B), not M10, because the PDF needs the files anyway. If the `@ibm/plex-*` npm packages lack the expected paths, the fonts are vendored with `OFL.txt` (about 2–3 MB in git).
- **Plex Sans Hebrew, not Noto,** for the PDF (matches the UI). Non-Hebrew/Latin scripts and emoji show U+25A1; a Noto fallback is deferred.
- **Bundle budget 300 KB gz** for `/[locale]` is a target, not a measured floor. If D's analysis shows it needs a framework-level change (for example dropping `@base-ui/react` in favour of one primitive library), the budget is set to the achieved number and the gap goes to M10.
- **Analytics:** topics trend uses `meeting_tags` (normalized, stable); free-form summary `topics` are not trended. Members with fewer than 3 meetings are folded into "others" in the admin breakdown. Admins get no private-meeting bypass.
- **Notifications** are polled (60 s); no websockets, email digest or push. Read rows are kept 90 days.
- **Service worker** never stores HTML (network-only navigations), which means no offline app shell beyond `offline.html`; the recorder works offline only in a tab that is already open.
- **Background Sync is Chromium-only;** elsewhere the queue flushes on load, `online` and focus. iOS Safari may evict IndexedDB after 7 days without use; the UI warns when `persist()` is denied.
- **Share passwords** move to scrypt; memory-repo legacy hashes still verify. No password complexity rule beyond 8–128 characters.
- **Turn undo** is all-or-nothing: if any segment of the turn changed since, the undo is refused (409) rather than partially applied.
- **Screenshots are not committed** (user decision, 2026-10-13): e2e and RTL screenshots go to the gitignored `test-results/m9-screenshots/` and are attached to the PR.
- **Relative times** render absolute on the server and switch after mount (a deliberate, hydration-safe flicker).
- **Out of scope:** notification email or push, a Hebrew-calendar date option, Arabic UI, translating provider-side M8 content, live transcript (M7 stretch).
