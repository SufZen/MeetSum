# M6: Search & AskMeetSum, implementation spec

Base `parity/m6-search`, stacked on `parity/m5-intelligence`. It assumes M2–M5 are integrated:
- M2: `withAuthz`, `AuthContext`, `toRepoScope`, `RepoScope`, `meetingScopeSql` (`lib/meetings/visibility.ts`), `getSystemMeetingRepository`, workspace-scoped API keys (`read ⊂ write ⊂ admin`).
- M3: `speakers` (display_name/label), `transcript_segments.turn_index`, `words jsonb`.
- M4: `transcript_version`, `lib/player/contract.ts` `usePlayer().seek`, `lib/player/citations.ts` `resolveCitation`, `lib/player/deep-link.ts` `buildSegmentLink` (`/<locale>?meeting=<id>&t=<sec>`), `GET /api/meetings/[id]/transcript`.
- M5: `lib/ai/llm` (`generateStructured`, router task `chat`, `recordLlmRun`, `estimateCostUsd`, `buildSharedSystem`), Gemini default `gemini-3.8-flash` with Claude optional, `lib/intelligence/transcript-format.ts` (`formatTranscriptForPrompt` aliases `s1..sN`, `estimateTokens`), `lib/intelligence/citations.ts` (`resolveRefs`, `quoteMatchesSegment`, `normalizeForQuote`), `lib/intelligence/language-check.ts` (`hebrewRatio`), IntelligenceV2 (`items`, `chapters`, `meetingType`, refs).

Migrations exist up to 022 (M5); M7 adds 024. This spec adds **025**. Step 0 renumbers the M8 spec to 026 and the M9 spec to 027 (see "Migration numbering"). The work is split into four parallel packages, A/B/C/D, with strictly disjoint file ownership, plus an orchestrator Step 0 that keeps the build green. No keys are needed to build, test, run the eval or run the e2e: SDKs are mocked, embeddings have a deterministic test provider, and chat has a replay stream.

## What the current code tells us
- **Search is ILIKE.** `listMeetingsPage({query})` builds `ILIKE '%q%'` over title, source, language, transcript segments, summary overview, action items and tags (`postgres-repository.ts` ~443-472). `searchMeetings` (~3718) wraps it.
  - `/api/meetings/search` loads 500 meetings and filters them in JS.
  - `/api/memory/ask` passes the whole question into ILIKE, so it almost never matches.
- **Memory ask returns no real answer.** `askMeetingMemory` (~3728) drops tokens of 3 characters or fewer and returns the overview.
  - `lib/memory.ts` `tokenize` drops tokens of 2 characters or fewer and has no prefix handling, so `תקציב` never finds `בתקציב` and `על`, `דו`, `AI` are dropped.
  - Room ask (`/api/rooms/[id]/ask`, `workspace:read`) runs `buildMeetingMemoryAnswer` over every room meeting.
- **`meeting.index` is a no-op (M1 already fixed the re-transcribe bug, a2ec203).**
  - `processIndexJob` (`processor.ts` ~1111) sets the stage, throws `UnrecoverableError` when there is no transcript, and otherwise returns `{indexed:false}`.
  - Nothing enqueues `meeting.index`. The summarize path only sets the stage label inline (~541). The PLAN note "it currently re-transcribes" is stale.
- `meetings` has no `updated_at` and no `meeting_type` column. `meetingType` lives only in the intelligence JSON.
- `runMigrations` (`lib/db/migrations.ts`) wraps each file in `begin/commit` and skips any version already in `schema_migrations`. Gaps and out-of-order files apply fine, but **a duplicate version is silently skipped**.
- The compose and prod Postgres image is `postgres:17-alpine` (musl). It mounts `db/migrations` into `docker-entrypoint-initdb.d`, so on a fresh volume 025 runs outside the runner too and must be idempotent.
- **MCP** (`mcp/server.mjs`):
  - It registers 8 tools and calls `server.connect()` at the top level, so it can't be tested.
  - `search_meetings` hits `/api/meetings?query=` (ILIKE) with no pagination.
  - `ask_meeting_memory` builds `/api/meetings/${meetingId}/ask` without `encodeURIComponent`.
  - `list_action_items` fans out over every meeting.
- **No SSE helpers exist.** `lib/rate-limit.ts` has presets `api, aiProcessing, exports, share, publicAccess, admin`.
- **UI:**
  - Memory panel `operational-pages.tsx` ~1336 (panel key `memory`).
  - `components/ask-meeting-panel.tsx` shows no citations.
  - `room-detail-view.tsx`.
  - `app/[locale]/tasks/page.tsx` is the precedent for a full page.
- M4's `lib/player/transcript-search.ts` `normalizeForSearch` is the client in-transcript finder. M6's normalizer is the server and index authority (follow-up: make M4 delegate to `foldText`).

## Decisions (normative)
- **Postgres image:** `pgvector/pgvector:0.8.1-pg17` (pinned tag; record the digest in the PR) in `docker-compose.yml` and `docker-compose.prod.yml`. PG17 kept (see "Postgres image").
- **pgvector is optional at runtime and pg_trgm is required.**
  - Migration 025 always creates `pg_trgm`, the chunk tables, FTS and trigram indexes.
  - The vector part (`vector` extension, `meeting_chunk_embeddings`, HNSW index) installs only when pgvector ≥ 0.8 is available. Otherwise it raises a NOTICE and search runs lexical.
  - Capabilities are feature-detected at startup and cached (`getSearchCapabilities`).
  - `npm run search:vector-setup` installs the vector part later, after the image switch, without a new migration.
- **Embeddings:** `gemini-embedding-001`, `outputDimensionality=1536`.
  - pgvector HNSW on `vector` caps at 2000 dimensions. 1536 is within noise of 3072 on Google's MRL numbers.
  - 1536 outputs are not pre-normalized, so the client L2-normalizes them.
  - **Model and dimensions are stored on every vector row** (`model`, `dimensions`).
  - The active key `{model, dimensions}` comes from env. A meeting whose `search_embedding_key` differs from the active key is stale and gets re-embedded.
  - There is one partial expression HNSW index per key: `((embedding::vector(D)) vector_cosine_ops) where model='<m>' and dimensions=D`. Queries use the same cast with **literal** validated model and dimensions so the partial index matches.
  - Old-key vectors are never mixed. The indexer deletes a meeting's other-key rows after embedding the active key.
- **Embeddings are keyed by content, not chunk id:** `(meeting_id, content_hash, model, dimensions)`. Rebuilding chunks (delete and insert) keeps vectors, and an edit re-embeds only the chunks whose hash changed.
- **Chunks are built from speaker turns.**
  - Consecutive segments with the same `turn_index` (legacy rows: speaker change) form a turn. Short turns are merged up to a minimum.
  - Chunks are capped at about 800 tokens (`MEETSUM_CHUNK_MAX_TOKENS=800`). A longer turn is split at segment boundaries; a single huge segment is split at a sentence, then a word.
  - Each chunk carries `segment_ids[]`, `segment_start_ms[]`, `segment_offsets[]`, `speaker_ids[]`, `start_ms` and `end_ms` for click-to-seek.
  - Intelligence is chunked too: summary, items (decisions/risks/questions/commitments/next steps), action items, chapters, and a `meta` chunk.
- **Hebrew normalizer (`lib/search/hebrew-normalize.ts`)** is the only text-folding authority. The indexer, query builder, snippet highlighter, in-memory engine and eval all import it.
  - It strips niqqud and cantillation, folds final letters on both sides (display keeps the original through offset maps), and handles geresh/gershayim and maqaf.
  - It strips prefixes `ו/ה/ב/כ/ל/מ/ש` and chains (`וש, כש, מה, וה, וב, של, שב, ושב, כשה…`), keeping at least `MIN_STEM_LETTERS=3` letters.
  - Short tokens are kept, never dropped.
  - Output feeds a `simple`-config tsvector: raw tokens at weight A, prefix-stripped variants at weight B. pg_trgm runs on the folded text.
- **Hybrid search.**
  - Three legs: vector top-K (cosine, only when capable), FTS (`ts_rank_cd`), and trigram (`word_similarity`, only when the DB locale yields Hebrew trigrams).
  - Weighted RRF fuses them (`k=60`; weights vector 1, fts 1, trgm 0.5).
  - **Visibility is applied before ranking.** Every leg's WHERE clause starts with `c.workspace_id = $ws` plus `meetingScopeSql(scope,'m',values)` plus filters, so fusion only ever sees scoped ids. Hydration re-applies scope.
  - Filters: date range, participants, rooms, tags, language, meeting type (plus speaker, source and kind).
  - Response `mode` is `hybrid` (all usable legs), `lexical` (no vector capability, no provider, or query embedding failed) or `empty`.
- **AskMeetSum.**
  - Scopes: meeting, room, workspace (all visible meetings).
  - Retrieval runs through B's `retrievePassages`. For a meeting whose transcript is at most `MEETSUM_ASK_FULL_TRANSCRIPT_TOKENS` (60k), full-transcript mode reuses M5's byte-identical shared prefix.
  - The answer streams over SSE from `POST /api/ask` (JSON mode for MCP and the CLI).
  - Model: M5 router task `chat`, so `gemini-3.8-flash` by default and Claude Sonnet when the workspace preference or env says so, with fallback only before the first delta.
  - Citations are mandatory aliases `[sN]` (segments) and `[aN]` (intelligence items), validated server-side against the aliases actually provided, as in M5's `resolveRefs`.
  - **No citation, no claim:** on `done`, sentences without a valid citation are removed (`MEETSUM_ASK_STRICT_CITATIONS=true`). If nothing remains, the answer becomes the localized refusal.
  - The answer language follows the question (Hebrew-first).
  - Threads are persisted per user and workspace. API-key principals are stateless.
- **Prompt-injection hygiene.**
  - The system prompt is a fixed constant per language (`ASK_PROMPT_VERSION`).
  - Transcript text is wrapped as escaped data in `<passage>` blocks and never reaches the system role or tools; no tools are passed.
  - Request free text (question, history) always comes after every cache breakpoint.
  - There is no server-side answer cache. The query-embedding LRU is keyed by `workspaceId|principalKey|modelKey|task|folded`, so nothing derived from one user's free text is reused for another user.
- **Cost (documented in `docs/architecture.md`, search section, by A):**
  - Indexing is about 42k embedding tokens per Hebrew meeting-hour (35k transcript, about 10% overlap, about 3k intelligence) × $0.15/MTok ≈ **$0.006 per meeting-hour**.
  - Storage is about 55 chunks × 6 KB ≈ 0.35 MB per meeting-hour (vectors) plus text.
  - A query embedding costs about $1.5e-6. A retrieval ask on `gemini-3.8-flash` (12k in, 700 out) is about $0.012; on Sonnet about $0.05.

## Postgres image (Step 0 + runbook)
- Both compose files use `postgres.image: pgvector/pgvector:0.8.1-pg17`. Debian images use the `en_US.utf8` locale, so pg_trgm yields Hebrew trigrams (alpine plus the C locale can't).
- **Decision (orchestrator, 2026-10-13): stay on PG17.** The current volumes are PG17, so `pgvector/pgvector:0.8.1-pg17` keeps the major version (no downgrade). Moving from alpine (musl) to Debian (glibc) still changes collation behaviour: after restore run `REINDEX DATABASE` and `ALTER DATABASE … REFRESH COLLATION VERSION`, or do a dump and restore.
- **Runbook** (PR body plus `docs/deployment`, orchestrator):
  1. `scripts/backup-postgres.sh` (plus a plain dump when downgrading).
  2. Create a new volume on the new image, restore, run `npm run db:migrate`.
  3. Run `npm run search:vector-setup` (no-op if 025 already installed vector), then `npm run search:backfill -- --all`.
- **Managed Postgres:** pgvector ≥ 0.8 is optional. Without it, search is lexical and the admin status says why.

Work items:
- **A1 Hebrew normalizer.**
  - Pipeline:
    1. NFKC.
    2. Strip cantillation U+0591–U+05AF and points U+05B0–U+05BD, U+05BF, U+05C1–U+05C2, U+05C4–U+05C5, U+05C7.
    3. Maqaf U+05BE, paseq U+05C0 and sof pasuq U+05C3 become separators.
    4. Remove geresh/gershayim (`׳ ״ ' " ’`) between or after Hebrew letters (`צה״ל→צהל`, `דו"ח→דוח`, `ג׳ירה→גירה`).
    5. Fold final letters `ך→כ ם→מ ן→נ ף→פ ץ→צ`.
    6. Lowercase Latin.
    7. Numbers: drop thousands commas (`1,200→1200`), keep `3.5`, `Q3`, `v2`.
    8. A hyphen-attached prefix letter (`ב-Supabase`, `ה-API`) becomes the bare word.
    9. Tokenize on everything else.
  - **Short tokens are kept.** Hebrew tokens of 2+ letters, every number, and Latin tokens of 1+ characters are indexed. A 1-letter Hebrew token is dropped only when it is a bare prefix letter.
  - `QUERY_STOPWORDS` (`של את על עם זה גם כי אם או אבל the a of to and`) only prunes the FTS OR group when other tokens remain. It is never applied at index time.
  - **Prefix variants** (Hebrew tokens of 4+ letters):
    - Chains match `^(ו)?(ש|כש|מש)?(ב|כ|ל|מ)?(ה)?`, covering `ו ה ב כ ל מ ש וה וב ול וש כש מה שה של שב ושב כשה…`.
    - Every strip point whose remainder has ≥ `MIN_STEM_LETTERS` (3) letters is emitted, longest remainder first, at most 3 per token (`והתקציב → התקציב, תקציב`).
    - Variants go to weight B, and the raw token is always kept, so exact matches rank higher.
  - Latin light stemmer (length ≥ 5): `-ies→y`, `-es`, `-s`, `-ing`, `-ed`.
  - `foldWithOffsets` maps every folded UTF-16 index back to an original index, so highlights land on the original surface text.
  - `detectTextLanguage`: Hebrew letter share ≥ 0.6 → `he`, ≤ 0.1 → `en`, otherwise `mixed`.
- **A2 Chunker** (`chunkTranscript`, pure, deterministic).
  - Turns: consecutive segments with equal `turn_index` (falling back to speaker change). Each turn's text is `"<name>: seg1 seg2…"`, where name = `displayName || segment.speaker || label`.
  - Packing:
    - Greedily merge whole turns until `tokens ≥ MEETSUM_CHUNK_MIN_TOKENS` (250), then close at the next turn boundary.
    - Never exceed `MEETSUM_CHUNK_MAX_TOKENS` (800). Force-close at a segment boundary and repeat the speaker label in the next chunk.
    - A single segment over the max is split at a sentence, then a word. Its pieces share the segment id with distinct offsets.
  - Overlap: prepend the trailing segments of the previous chunk, up to `MEETSUM_CHUNK_OVERLAP_TOKENS` (80). `overlap_count` counts them.
  - `start_ms`/`end_ms` cover the chunk's own segments only.
  - `language` = majority segment language (falling back to the meeting language). `speaker_ids` = distinct.
  - Token estimate = M5 `estimateTokens` (one estimator everywhere).
  - Boundaries are anchored to turns, so a one-segment edit changes at most 2 chunk hashes in the common case.

- **B1 Query** (`query.ts`): `buildTsQuery(nq)`.

- **B2 SQL** (`sql.ts` + `filters.ts`, pure builders returning `{text, values}`).
  - Base: `from meeting_chunks c join meetings m on m.id = c.meeting_id where c.workspace_id = $ws and <meetingScopeSql(scope,'m',values)> and <filters>`.

    - Scope kinds: `meeting` adds `m.id = $id`; `room` adds the room filter.
  - Filters:
    - `m.started_at >= $from` and `< $to + 1 day`.
    - participants: `exists (select 1 from meeting_participants p where p.meeting_id = m.id and (lower(p.email) = any($) or p.name = any($)))`, with names matched on `foldText`.

    - rooms: `exists (select 1 from meeting_contexts mc join contexts x on x.id = mc.context_id and x.workspace_id = m.workspace_id where mc.meeting_id = m.id and mc.context_id = any($))`.

## Security checks (each needs a test; reviewers verify)
1. **Visibility before ranking.** Every SQL leg (vector, FTS, trigram), hydration, facets, retrieve and thread joins include `workspace_id = $ws` plus `meetingScopeSql`. Recording-SQL tests assert the predicate precedes `order by`/`limit`.

5. **Prompt injection.**
   - The fixed system prompt never contains user input.
   - Transcript and titles are escaped data.
   - Alias lookalikes inside data are neutralized.
   - No tools are passed. The model output is plain text rendered without HTML, links or images.
   - Unknown aliases are dropped and quotes come from segment text.
6. **No cross-user caching.** No answer cache. The query-embedding cache key includes `principalKey`. No cached LLM block contains the question or history of another thread. Replay stream and hash embedder are disabled in production.
7. **Threads are private.** Every thread statement filters by `user_id` and `workspace_id`. Admins can't read others' threads. Questions are not audited (privacy); costs show in `ai_runs`.
8. **Abuse limits.** Rate limits `search` 60/min and `ask` 20/min, the daily ask cap, `q` ≤ 300 and question ≤ 2000 characters, output token cap, SSE keep-alive and abort release LLM streams.
9. **Data minimization.** `chat_messages.retrieval` stores ids and scores only. The eval report and `ai_runs` metadata hold no transcript text. Logs never print questions or passages.
10. **MCP.** Ids are encoded in paths. A workspace-scoped key is required. Responses are truncated. 401/403 messages give no hints about other workspaces.
11. **Migration safety.** 025 applies with and without pgvector (transactional, idempotent). Duplicate migration versions fail CI.

## Defaults (flag in PR)
- **pgvector is optional:** absent → lexical (FTS + trigram) with a visible badge. The in-memory/demo mode is lexical only.
- **Postgres image** pinned to `pgvector/pgvector:0.8.1-pg17` (same major version as today; no downgrade).
- **Embeddings:** 1536 dimensions. Changing model or dimensions means `search:vector-setup --key` plus sweeper re-embed. Vertex batching is an assumption to verify.
- **Normalizer:** `MIN_STEM_LETTERS=3`. Rare prefix false positives (e.g. `שלום`→`לום`) are accepted at weight B.
- **Chunks:** min 250, max 800, overlap 80 tokens.
- **Citations:** strict mode is on (uncited sentences dropped).
- **Threads** are private; admins can't read them. Questions are not audited.
- **Rough costs:** indexing about $0.006 per meeting-hour; retrieval ask about $0.012 (Gemini) or $0.05 (Sonnet); meeting-scope ask with a cache hit about $0.004 on Gemini.
