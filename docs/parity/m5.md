# M5: Intelligence parity, implementation spec

Base `parity/m5-intelligence`, stacked on `parity/m4-player`. It assumes M2, M3 and M4 are already integrated: `withAuthz`/`ctx.meetings`/`RepoScope`/`workspace_settings`, the M3 `speakers` + `words jsonb` + `ai_runs.workspace_id`, and an M4 player context plus media endpoint. Migrations go up to 020 (M3) and 021 (M4, reserved). This spec adds **022**.

There are four parallel packages, A/B/C/D, with disjoint file ownership. The orchestrator commits Step 0 first. No keys are needed to build or test: the LLM SDKs are mocked in unit tests, and the eval harness can replay recorded outputs.

## What the current code tells us
- **Summaries are single-provider and English-only.** `GeminiSummaryProvider` (`lib/ai/providers.ts` ~822-991) is the only LLM path. Its prompt is English, it uses an inline `Type` schema, and `getLastRun()` reports provider and model only. No tokens or cost are recorded, and `ai_runs.cost_estimate` is never written for summaries.
- **Hebrew prompt helpers are dead code.** `lib/ai/policy.ts` has `summarizeInHebrewPrompt` and `shouldEscalateTranscription`, but nothing calls them.
- **Templates are only English prompt addenda.** `summary-templates.ts` has six of them, chosen by the workspace `summaryTemplate` setting (`getTemplateAddendum`). There is no per-meeting template, no sections schema and no custom templates. M2 deletes `aiProviderPreference`, so M5 owns provider selection.
- **Intelligence is stored as one JSON blob.** It goes into `intelligence_runs.output` (latest row wins), plus `summaries`/`summary_sections` (decisions only), and tags into the global `tags`. Summary items (decisions, risks, and so on) are plain strings with no ids, so they can't be commented on or cited.
- **Action items have most of the fields but weak data.** `due_date timestamptz`, `priority`, `owner` (free text), `source_start_ms`, and the M1 `edited_by_user/origin/original_title/completed_at` columns exist. There is no workspace_id, no owner linkage and no raw due phrase. `mergeActionItems` already protects user work and is reused unchanged. The `PATCH /api/action-items/[id]` route already sets `edited_by_user`.
- **Meeting-type UI is a placeholder.** In `meeting-workspace.tsx` the Prep tab is placeholder text and the Follow-up tab just shows `followUpDraft`. The Tasks tab is a checkbox list.
- **Shares have no scope.** `meeting_shares` has no scope column. A clip token must never resolve as a meeting share.
- **Analytics must read words, not text.** `cleanupTranscriptSegments` strips fillers from segment text, so filler rate has to come from the M3 raw `words`. If there are no words, analytics falls back to text and flags it.
- **Re-transcription changes segment ids.** M3 `replaceTranscript` re-inserts segments, so comments and clips need a time anchor (`startMs`), not just a segment id.

## Normative model
- **Output language.** `resolveOutputLanguage(meeting, settings)`:
  - `summaryLanguageMode` = `meeting` (default) uses `languageMetadata.primaryLanguage`.
  - `mixed` becomes `he` if the Hebrew letter share is at least 30%, otherwise `en`.
  - Unknown falls back to the workspace default language (`he`).
  - The run API can override it with `language`.
  - Quotes always stay in their original language.
- **IntelligenceV2.** `lib/intelligence/types.ts` is additive, so legacy readers keep working:
  - `version?: 2`, `title?`, `meetingType?`, `topics?: string[]` (free-form, in the meeting language, at most 8).
  - `chapters?: Chapter[]`, `sections?: TemplateSectionOutput[]`, `items?: SummaryItem[]`, `generation?: IntelligenceGeneration`.
  - Legacy `decisions/risks/openQuestions/commitments: string[]` stay populated, derived from `items`, so exports, share, webhooks and RealizeOS are untouched.
  - `MeetingTag` (enum) stays as the filter tag set.
- **SummaryItem.** `{id, kind: decision|risk|open_question|commitment|next_step|section_item, sectionKey?, text, refs: {segmentId,startMs}[]}`.
  - `id = "si_" + sha1(kind + normalizeTaskTitle(text)).slice(0,12)`. This is stable across regenerations when the text is unchanged.
- **Chapter.** `{id, title, summary, startMs, endMs, startSegmentId, bullets[]}`.
  - Starts are monotonic. The first chapter snaps to the first segment, and `endMs` is the next chapter's start (the last one ends at the transcript end).
  - Target 3–12 chapters per hour, each at least 2 minutes. Outline = chapters + bullets.
- **SmartTask additions.** `ownerText, ownerParticipantId, ownerSpeakerId, ownerUserId, dueText, dueOn (YYYY-MM-DD), dueSource: parser|ai|user, sourceSegmentId`. `owner` stays as the display name.
- **Transcript serialization for prompts.** `formatTranscriptForPrompt(segments, speakers)` produces lines like `[s12 03:41 דנה] text`, with aliases `s1..sN` mapped back to segment ids, and resolved speaker names from M3.
  - Models cite aliases only. Unknown aliases are dropped.
  - If a quote is not a normalized substring of the segment it cites, the citation is dropped (the faithfulness guard).
  - If the estimated tokens exceed `MEETSUM_LLM_MAX_TRANSCRIPT_TOKENS` (300k), map-reduce over 30-minute windows.
- **Hebrew style guide** (`lib/ai/prompts/style-guide.ts`, he and en versions):
  - Write in the output language with natural Israeli business register.
  - When gender is unknown, use gender-neutral forms: name, plural, infinitive or noun ("יש לשלוח", "דנה תשלח" only if known). Never assume masculine.
  - Keep English tech terms and product names in Latin script (Supabase, API, PR). No transliteration, no niqqud.
  - Dates `DD.MM.YYYY` with the weekday name. 24-hour times. Money as `1,200 ₪` / `$1,200`. Digits for every number in money, percentages, dates and anything ≥ 10.
  - Use Hebrew punctuation and no bidi control characters.
  - Never invent anything. Mark uncertainty with "(לא ברור מהתמלול)".
  - Plus one compact Hebrew few-shot example (`lib/ai/prompts/examples/he-business.ts`, synthetic).
- **Language check** (`language-check.ts`, pure). `hebrewRatio` = Hebrew letters / all letters, after removing Latin tokens that are tech terms (glossary plus a `[A-Za-z0-9._-]+` token allowance).
  - `he` passes at ≥ 0.6. `en` passes when the Hebrew ratio is ≤ 0.1.
  - On failure: one retry with a corrective system line. If it fails again, accept the output, set `generation.languageCheck="failed"`, and raise quality warning `summary_language_mismatch`.
- **Model routing** (`lib/ai/llm/router.ts`). The preference comes from the workspace `llmProviderPreference` (`auto|anthropic|gemini`), with `MEETSUM_LLM_ROUTES` (JSON) as an override.

| Task | anthropic | gemini | auto (until eval decides) |
|---|---|---|---|
| summary (core, incl. chapters/items/tasks), prep_brief, follow_up, chat (M6) | `claude-sonnet-5-5` | `gemini-3.5-flash` | gemini for summary; sonnet for prep/follow_up when configured |
| title_tags_type, extraction, sentiment | `claude-haiku-5-5` | gemini | haiku if configured, else gemini |
| judge (eval only) | `claude-opus-5-5` | — | opus |

  - Fallback chain: primary, then the other provider if configured, then (summary only) the heuristic fallback, with `fallbackUsed` set.
  - A refusal on Haiku goes to the next provider.
- **Template precedence:** `meetings.template_key`, then workspace `summaryTemplate`, then `auto`. In `auto`, the first Haiku call (title_tags_type) classifies `meetingType`, and that maps to a built-in. Hebrew meetings with no match use `hebrew_business`.

- **A1 Anthropic provider** (`llm/anthropic.ts`, `@anthropic-ai/sdk`):
  - Client is `new Anthropic({ apiKey, maxRetries: ANTHROPIC_MAX_RETRIES (3), timeout: ANTHROPIC_TIMEOUT_MS })`. The SDK retries 408/409/429/5xx.
  - Request layout: `system: [{type:"text", text: preamble + styleGuide(lang) + "<transcript>…</transcript>", cache_control:{type:"ephemeral", ttl: MEETSUM_LLM_CACHE_TTL ("5m")}}]`, then `messages:[{role:"user", content: instructions}]`. The transcript prefix is byte-identical across summary, prep and follow-up on Sonnet, and across title and sentiment on Haiku (no timestamps or ids in the prefix).
  - Structured output via `output_config:{format:{type:"json_schema", schema}}`, with the schema from `z.toJSONSchema` run through `toProviderSchema()` (adds `additionalProperties:false`, all fields required, nullable through type unions, strips unsupported keywords).
  - Response parsed and validated with zod. One repair retry on zod or `validate()` errors, otherwise `invalid_output`.
  - No prefill, no forced `tool_choice`, `thinking` omitted (adaptive). `output_config.effort`: Haiku `low`, Sonnet summary `medium`, judge `high`.
  - Sonnet and Opus calls go through `client.beta.messages` with `betas:["server-side-fallback-2026-07-01"], fallbacks:"default"` when `ANTHROPIC_SERVER_FALLBACK=true` and the request is not a batch. ## Acceptance
1. Migration 022 applies on M2–M4 data. Legacy intelligence (v1) renders through `normalizeIntelligence`. Existing action items keep owner and due (backfilled into `owner_text`/`due_on`).
2. With only `GOOGLE_GEMINI_API_KEY`, the pipeline produces a Hebrew V2 summary for a Hebrew fixture, with no Anthropic calls. With only `ANTHROPIC_API_KEY`, Sonnet summarizes and Haiku does title, tags and sentiment. With neither, the heuristic V2 runs and `ai_runs` shows the fallback.
3. Each LLM call writes an `ai_runs` row with tokens, cache tokens, `cost_estimate`, prompt_version and template_key. The second Claude task on the same meeting shows `cache_read_tokens > 0` (mocked usage in tests, verified live once).
4. Hebrew summaries pass the language check. They keep Latin tech terms, use gender-neutral phrasing when gender is unknown, and format dates as DD.MM.YYYY. An English output for a he meeting is retried, then flagged.
5. Chapters are monotonic, cover the transcript and seek on click. Every citation maps to an existing segment, and invented quotes are dropped.
6. Templates: all 7 new built-ins plus the legacy keys resolve. A custom workspace template with sections drives the schema. A per-meeting template override plus regenerate works. `auto` picks via meetingType.
7. Due dates: the parser test matrix passes. A task "עד יום ראשון" from a meeting on Thursday 15.10.2026 gets due 18.10.2026. User edits survive regeneration (M1).
8. Owners resolve to M3 speakers/participants/members. The Tasks view (mine/open/overdue/room) returns only visible meetings' tasks.
9. Clips are created from a range or from segments, play via the M4 player, and render a clip-only audio object. A clip share link exposes only that clip, and a private meeting gives 409. A clip token never opens the meeting.
10. Comments are threaded, viewer can comment, mentions are restricted to members and create notification rows. Reactions toggle. Segment comments survive re-transcription via re-anchoring.
11. The analytics card shows talk-time ratio, longest monologue, questions per speaker, WPM, filler rate (from raw words) and per-speaker sentiment. It updates after speaker merge without reprocessing.
12. Prep brief cites related meetings and open tasks. Follow-up email generates in he/en across three tones.
13. Eval replay runs with no keys and produces `llm-eval.md` (no transcript text). The live mode is documented, and the decision rule is applied.
14. All green; no real network in tests.
