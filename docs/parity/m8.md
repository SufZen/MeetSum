# M8: Integrations (Fireflies parity), implementation spec

**Base branch:** `parity/m8-integrations`, stacked on the M7 branch (migrations up to 024 present). M8 starts at **025**.

**Shape:**
- Four parallel packages, A–D, with strictly disjoint file ownership.
- **Step 0** (orchestrator) commits the migration, the contracts and no-op stubs, so every branch stays green.
- The **Integration step** wires the real pieces together and adds the global tests.
- The UI follows design-system README §7–10:
  - integrations live in Settings, not on a right rail;
  - status pills appear only for exceptions;
  - names, emails and account labels go in `<bdi>`;
  - logical CSS only;
  - `dir` comes from the known language.

## Findings in the current code that shape the design
1. **Notion export (`app/api/meetings/[id]/export/notion/route.ts`, `lib/integrations/notion.ts`) has five problems:**
   - The token comes in the request body and the route is admin-only.
   - The first 50 transcript segments are joined into **one** `code` block. That is over Notion's 2000-character `rich_text` limit, so real meetings fail with a 400.
   - Nothing enforces the 100-children-per-request limit.
   - The properties are hard-coded (`Name`, `Date`, `Status`, `Source`, `Language`, `Participants`), so any database without exactly those properties returns a 400.
   - The headings are English only.
2. **DOCX: the route exists but has no UI.**
   - `POST /api/meetings/[id]/export/docx` → `renderMeetingDocx` (`lib/meetings/export.ts:196`) has no bidi, forces `AlignmentType.LEFT`, uses English headings and the server-locale `toLocaleString()`.
   - The filename regex strips Hebrew, so Hebrew titles fall back to `meetsum-export`.
   - No UI calls it: `downloadExport` (`components/command-center-shell.tsx:853`) only accepts `"pdf" | "markdown"`, and the right rail offers PDF, MD and RealizeOS.
3. **One hook point for events.** `deliverPlatformEvent` (`lib/jobs/processor.ts:251`) emits `summary.created`, `action_item.created` (once per new item) and `meeting.completed`. It already re-reads visibility and minimizes private payloads (`platformEventData`). The `meeting.completed` payload is thin (`{meetingId, title}`).
4. **The n8n templates are broken.** They read `$json.payload.*`, but the envelope is `{id, name, occurredAt, workspace_id, data}`, and n8n's Webhook node exposes the request under `$json.body`. None of them verify `x-meetsum-signature`.
5. **`calendar_events.google_identity_id` and `google_event_id` are `NOT NULL`.** Outlook events cannot be stored without a schema change. M7's `syncCalendarBotSession({workspaceId, subject, calendarEventId, meetingId, event: CalendarEventLike})` and `extractCalendarMeetingLink` work on a Google-shaped event, so Outlook events get mapped into `CalendarEventLike`.
6. **Existing Azure app variables.** `AZURE_TENANT_ID`, `AZURE_CLIENT_ID` and `AZURE_CLIENT_SECRET` are used app-only for Teams subscriptions (`lib/capture/teams-subscriptions.ts`). The delegated Graph app may be the same Entra app, so each `MS_*` variable falls back to its `AZURE_*` counterpart.
7. **Google DWD clients ignore scopes in one strategy.** With the `user-oauth` strategy, `createDelegatedGoogleClient` ignores the requested scopes. The Google Docs DWD path therefore only works with the private-key or keyless strategies; the primary path is per-user OAuth.
8. **`lib/auth/secret-crypto.ts` has one key and no AAD,** and it falls back to `MEETSUM_SESSION_SECRET`. A ciphertext copied from one row to another would still decrypt.
9. **`rate-limit.ts` is in-memory per process,** so caps that matter (rule counts, connection counts, recipients) are also enforced in the DB.
10. **`EmailMessage` has no custom headers,** so List-Unsubscribe and Auto-Submitted can't be set. M5's `meeting_generated_docs.follow_up_email` exists and may be included in the recap; it is not required.
11. **Leftovers.** `integration_endpoints` (legacy, unused) is left in place and dropped in M10. M5 deferred calendar/ICS export to M8: it is **out of scope** here and stays a backlog item.

## Model and rules (normative)
- **Connection.**
  - A connection is one OAuth grant: `(workspace, provider, user_id?, external_account_id)`.
  - **Workspace connections** (`user_id` null): `slack`, `notion`, `hubspot`. They need `integrations:manage` (admin).
  - **Personal connections** (`user_id` = me): `microsoft` and `google_drive`. They need the new permission `integrations:connect` (member and up). Only the owner can configure one; admins see its label and status and can revoke it.
- **Token secrecy.**
  - `access_token_enc` and `refresh_token_enc` use `encryptSecret(value, aad)` with `aad = "${workspaceId}:${connectionId}:${field}"`.
  - Tokens are never selected into DTOs, logs, audit records, errors or job payloads. Errors are redacted and capped at 500 characters.
- **OAuth flow** (`lib/integrations/core/oauth-state.ts`).
  - **Start:**
    1. Authz: `integrations:manage` for workspace providers, `integrations:connect` for personal providers.
    2. Insert `integration_oauth_states(nonce = 32 bytes base64url, workspace_id, user_id, provider, code_verifier_enc, return_to, expires_at = now + 10 min)`.
    3. `state = base64url(json{v:1, n: nonce, p: provider, ws, u, exp}) + "." + HMAC-SHA256(key = HKDF(MEETSUM_SESSION_SECRET, "meetsum:integration-oauth-state"))`.
    4. Set the cookie `meetsum_int_oauth = nonce` (httpOnly, `Lax`, `path=/api/integrations`, 10 min, secure in production).
    5. Redirect (302) to the provider.
  - **Callback** (`withSession`). In order:
    1. The signature is valid and `exp` has not passed.
    2. Cookie nonce = state nonce = DB row; `used_at` is null; mark it used atomically (`update … where used_at is null returning`).
    3. Session user = `state.u`, and that user is a current member of `state.ws` with the required permission (re-checked).
    4. Route provider = `state.p`.
    5. Exchange the code with the `code_verifier` (PKCE S256 for `microsoft` and `google_drive`; off for Slack, Notion and HubSpot unless verified later).
    6. Upsert the connection, audit it, and redirect to `return_to` (`safeReturnTo`, defaulting to `/{locale}?panel=settings#integrations`).
  - Any failure → redirect with `?integration_error=<code>`. Nothing reflects provider text.
- **Redirect URI** = `${MEETSUM_OAUTH_REDIRECT_BASE ?? NEXT_PUBLIC_APP_URL}/api/integrations/{provider}/oauth/callback`. It must be https in production and is never taken from the request.
- **Outbound calls go only through `providerFetch(provider, url, init)`:**
  - https only, with an exact host match against `PROVIDER_HOSTS` (below) and no env override;
  - `redirect: "error"`, 15 s timeout, 2 MB response cap;
  - the Microsoft tenant segment is validated (GUID, `organizations`, `common`, or a verified domain regex).
  - Errors become `ProviderError {kind: auth|forbidden|not_found|invalid|rate_limited|retryable|config, retryAfterMs?, providerCode?}`.
  - `kind: auth` → connection `needs_reauth`, the delivery fails without retrying, and the connection creator gets an M5 notification (`kind: integration_reauth`).
- **Token refresh** (`getAccessToken(connectionId)`):
  - Refresh when `expires_at − 120 s < now`, inside a transaction with `select … for update` on the connection row, so concurrent jobs can't race a rotating refresh token (Microsoft, and Slack with rotation enabled).
  - Always persist a newly returned refresh token.
  - `invalid_grant` → `needs_reauth`.
- **Disconnect:**
  1. Best-effort provider revoke (Slack `auth.revoke`, HubSpot `DELETE refresh-tokens`, Google `revoke`; Microsoft and Notion have none).
  2. Null the token columns and set `status = revoked`.
  3. Dependent rules → `enabled = false`, `disabled_reason = 'connection_revoked'`.
  4. Audit.
- **Rules** (admins only, workspace scope).
  - Columns: `trigger_event ∈ {meeting.completed, summary.created, action_item.created}`, `filters`, `destination`, `content`, `include_private`, `created_by_user_id`.
  - **Filters** (all optional, AND-ed):
    - `roomIds[]`: meeting contexts;
    - `tagNames[]`: any match;
    - `participantDomains {mode: "any_external"|"includes"|"excludes", domains[]}`. Internal domains are the domains of member emails plus `MEETSUM_BOT_INTERNAL_DOMAINS`;
    - `visibility[]`: default `["workspace", "link"]`;
    - `languages[]`, `sources[]`, `minDurationMinutes`.
  - **Content:** `{overview: true, actionItems: true, decisions: true, openQuestions: false, transcript: false, link: "app"|"existing_share"|"none"}`. A rule never creates share links, because that would flip visibility to `link`.
- **Privacy gate** (pure, `lib/integrations/core/privacy.ts`). It runs at dispatch **and again at deliver time**, after re-reading the meeting:
  - Private meeting → allowed only if `rule.include_private && rule.created_by_user_id === meeting.ownerUserId`; otherwise `skipped/private_meeting`.
  - Unknown visibility → treated as private.
  - Rule creator no longer a member → `skipped/rule_owner_inactive`, and the rule is auto-disabled.
  - **Manual sends:** private meetings need `canManageMeeting`. Invisible meetings → 404.
- **Delivery** (`integration_deliveries`) is the system of record. No `jobs` rows are written: it runs on a separate queue `meetsum-integrations`, the same reasoning as M7, so a long ASR job can't delay deliveries.
  - **Idempotency key:**
    - rule: `rule:{ruleId}:{event}:{meetingId}[:{actionItemId}]`, at most once per rule per meeting per event, and reprocessing does not re-post;
    - manual: `manual:{uuid}`.
  - **Multi-call providers** (Notion appends, HubSpot meeting + tasks, email per recipient) checkpoint in `progress`, so a retry resumes and never duplicates.
  - **Statuses:**
    - `queued` → `running` → `sent`;
    - `retrying` between attempts;
    - `partial`: some recipients or tasks failed after the last attempt;
    - `skipped`, with a `skip_reason`;
    - `failed`;
    - `cancelled`.
  - `external_ref` holds only identifiers and URLs (Slack `{channel, ts, permalink}`, Notion `{pageId, url}`, HubSpot `{meetingId, taskIds}`, Docs `{documentId, url}`), never content.
- **Isolation.** Every table has `workspace_id`. Every store function takes `workspaceId` and filters on it. Child IDs (rule → connection, delivery → rule) are joined within the workspace, and other-workspace IDs → 404. A rule can only reference a connection in its own workspace, enforced in the store and by a DB trigger-free check in an `insert … select`.
- **Caps** (enforced in the DB; exceeding one → 409):
  - 20 connections and 50 rules per workspace;
  - 50 rules evaluated per event;
  - 50 recipients per recap (`MEETSUM_EMAIL_RECAP_MAX_RECIPIENTS`).

## Package A: framework, routes, worker, settings UI
**Owns:**
- `lib/integrations/core/**`: `types`, `registry`, `oauth-state`, `pkce`, `http` (`providerFetch`, `PROVIDER_HOSTS`), `connection-store` (postgres + memory), `tokens` (`getAccessToken`/refresh/revoke), `rules-store`, `rule-filters`, `privacy`, `dispatcher`, `delivery-store`, `queue`, `worker`, `links`, `limits`, `dispatch-hook`.
- Routes: `app/api/integrations/[provider]/oauth/start`, `[provider]/oauth/callback`, `connections` (+`[id]`, `[id]/options/[picker]`, `[id]/test`), `rules` (+`[id]`), `deliveries` (+`[id]`, `[id]/retry`), `app/api/meetings/[id]/integrations/send`.
- `worker/index.ts` (integration worker body).
- `components/integrations/**`, **except** `components/integrations/providers/**`.
- `components/admin/admin-panel.tsx`.
- `lib/i18n/m8/integrations.ts`.
- `lib/rate-limit.ts` (the `integrationsOAuth` preset: 10/min).

**A1. OAuth.** State, nonce table, cookie binding and PKCE, as in the Model. Start validates `provider ∈ registry` and that the provider is configured (env present; otherwise 409 `integration_not_configured`). A daily sweep deletes expired states.

**A2. Connection store and tokens.**
- The store does an encrypted upsert on `(ws, provider, user, externalId)` and supports reconnecting a `needs_reauth` connection.
- DTO mapping excludes tokens.
- `PATCH` updates only the config allowlist per provider: Slack `defaultChannelId`, Notion `defaultDatabaseId`, HubSpot `defaultDealId`, Microsoft `calendarSyncEnabled`, `allowManualSend`.
- `POST [id]/test` makes a provider no-op call (Slack `auth.test`, Notion `users/me`, Graph `/me`, HubSpot `access-tokens`).

**A3. Rules API.**
- zod validation; the destination must match the connection's provider; caps.
- `validateDestination` checks the destination with the provider (for example, the channel exists).
- `include_private` is stored only when the creator is the saving user. Editing a rule by another admin resets `include_private = false` and stamps the new `created_by_user_id`, so private access always belongs to the person who saved it.

**A4. Dispatcher** (`integration.dispatch`, `jobId = integration.dispatch:<eventId>`):
1. Load the enabled rules for `(ws, event)`.
2. Load meeting facts with the system repo of `ws`: visibility, owner, contexts, tags, participant emails, language, source, duration.
3. Apply the rule-owner check, the privacy gate and the filters.
4. `insert … on conflict (idempotency_key) do nothing`, as `queued` or `skipped`.
5. Enqueue `integration.deliver` for each new queued row.

**A5. Deliver** (`integration.deliver`, `jobId = deliveryId`, `attempts = MEETSUM_INTEGRATION_MAX_ATTEMPTS`, custom backoff that uses `ProviderError.retryAfterMs` when present, else exponential from 30 s):
1. Lock the row; terminal states are a no-op.
2. Re-read the meeting and re-run the privacy gate.
3. `buildMeetingRecap`, then `provider.deliver`.
4. Map errors: `auth|forbidden|invalid|not_found|config` → `UnrecoverableError` + failed; `rate_limited|retryable` → retrying.
5. On the final attempt: `failed`, or `partial` if `progress` shows partial success.

Worker concurrency is `MEETSUM_INTEGRATIONS_CONCURRENCY=4`, with a global limiter of 20 jobs/s. Provider `jobs` handlers run as `integration.job` `{provider, job, workspaceId, connectionId}`. A repeatable `integration.tick` (every `MEETSUM_MS_CALENDAR_SYNC_MINUTES`) enqueues the per-connection jobs that providers declare, with `jobId = <provider>.<job>:<connId>:<timeBucket>`.

**A6. Manual send.**
- `POST /api/meetings/[id]/integrations/send {connectionId, destination?, content?}`.

**B1. Recap and bidi.**
- `buildMeetingRecap` honours the content toggles. It includes the transcript only when `content.transcript` is set, and uses M5 items for decisions and open questions when present.
- `dir` comes from the meeting language: `he`, `ar` and `fa` → rtl.
- `chunkText(text, max = 2000)`:
  - splits by paragraph, then sentence, then word, then grapheme (`Intl.Segmenter`);
  - measures length in UTF-16 code units and never splits a surrogate pair or grapheme cluster;
  - every chunk is ≤ `max`, and joining the chunks reproduces the text exactly, apart from whitespace at the split points.
- `rtlLine(line)` prefixes U+200F in RTL contexts when the line starts with a neutral or LTR character (digit, Latin name, bullet, emoji).
- `isolateLtr(token)` wraps timecodes and emails as `LRM…LRM` for Slack, Notion and plain text. DOCX and Docs use LRI…PDI or runs.

**B2. Slack.**

  - `ratelimited`/429 → `rate_limited` with `Retry-After`;

- **`buildSlackRecapMessage(recap, {locale, timeZone})`** (pure):

**B3. Notion.**

- **Exchange:** `POST https://api.notion.com/v1/oauth/token` with Basic auth (`client:secret`).

## Acceptance
1. Tokens are encrypted with AAD and never appear in any API response, log, audit record or job payload. Disconnect wipes them and disables dependent rules.
2. OAuth state is signed, single-use, cookie-bound, and bound to workspace + user + provider. Every tamper or replay case is rejected. Redirect URIs come only from env.
3. Outbound HTTP reaches only the allowlisted provider hosts, with redirects refused.
4. Rules fire on `meeting.completed`, `summary.created` and `action_item.created`, with filters (room, tag, participant domain, visibility). They are idempotent per rule, meeting and event, retry with backoff and `Retry-After`, and every attempt is visible in the delivery log with retry.
5. Private meetings are never sent by a rule unless the rule owner is the meeting owner and opted in. Visibility is re-checked at delivery time.
6. **Slack:** OAuth v2, channel picker, Block Kit recap within the limits, Hebrew lines RLM-prefixed, an "Open in MeetSum" link.
7. **Microsoft:** per-user Graph connection syncs Outlook events (delta); Teams, Zoom and Meet links feed M7 bot scheduling; events already synced from Google are not duplicated; private or confidential events create private meetings.
8. **Notion:** the OAuth connection replaces the token-in-body route; pages are created in the chosen database with every rich_text ≤ 2000 and appends in batches of ≤ 100 that resume on retry.
9. **HubSpot:** participants are matched by email; the meeting or note is logged and associated to contacts and the chosen deal; tasks are created from action items; retries don't duplicate.
10. **Email recap:** opt-in per workspace or room, he/en, RFC 2047, signed one-click unsubscribe, private visibility respected, one email per recipient.
11. Google Docs export creates a doc with RTL Hebrew paragraphs; the DOCX button works and produces bidi Hebrew; filenames keep Hebrew.
12. The event catalog has schemas validated against the real payload builders; the n8n templates are fixed and verify signatures.
13. Workspace isolation tests, the token-leak test, the private-exfiltration test and the route-coverage test pass; all checks are green; browser check in he and en.

## Risks and defaults (flag in the PR)
- **Slack `chat:write.public`** is added so the app can post without an invite; remove it via `SLACK_SCOPES` if the owner objects.
- **Notion version** is pinned to `2022-06-28`; the data-source API migration is deferred. Notion RTL behaviour is verified empirically in B3.
- **HubSpot association type IDs** and Notion and Graph delta field details must be verified against current provider docs and fixtures before merge.
- **Microsoft delegated permissions:** `OnlineMeetings.Read` may need tenant admin consent; sync degrades to `joinUrl` and links found in the event body.
- **Rule edits:** editing a rule resets `include_private` to the editor's ownership. Manual sends of private meetings are owner-only, because admins can't see private meetings.
- **Secret keys:** the same encryption key is used for Google and integration tokens; key rotation is deferred to M10.
- **Out of scope:** Zapier app, ICS export, Salesforce/Pipedrive/Jira/Asana, Slack slash commands or interactivity, Graph push (stretch only).
- **External inputs needed:**
  - Slack app (scopes, redirect `…/api/integrations/slack/oauth/callback`);
  - Entra app (delegated scopes, redirect, a client secret, admin consent if required);
  - Notion public integration (read and insert content capabilities, redirect);
  - HubSpot public app (scopes, redirect);
