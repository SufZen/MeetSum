# M8: Integrations (Fireflies parity), implementation spec

**Base branch:** `parity/m8-integrations`, cut from `main` at `c728764` (M0–M7 merged, #16–#25). Migrations exist up to **026** (024 M7 bot, 025 M6 search, 026 M6 ask usage). M8 adds **027**. M9 stays at 028.

**Shape:**
- **Step 0** (orchestrator) commits migration 027, the frozen contracts, the real shared helpers (`bidi`, `recap`, AAD encryption), no-op stubs, route stubs with permissions, the `.env.example` block and the authz coverage entries. The build stays green and behaviour is unchanged.
- **Four parallel packages, A–D,** with strictly disjoint file ownership:
  - **A:** OAuth core, encrypted token store, rules, dispatcher, delivery worker, Slack, email recap.
  - **B:** Microsoft Graph (Outlook calendar into M7 bot rules), HubSpot.
  - **C:** Notion OAuth, Google Docs, DOCX RTL plus the export button, the webhook event catalog.
  - **D:** the integrations settings page, per-meeting integration controls, i18n, the runbook, the browser e2e with fake providers.
- The **Integration step** wires the real pieces together and adds the global isolation, token-leak and private-exfiltration tests.
- **No live credentials exist.** Every provider is built and tested against recorded fixtures or fake HTTP. Unit tests inject `fetch`; the e2e runs a local fake-provider server. The live checklist is `docs/runbooks/integrations.md` (see "External apps checklist").
- The UI follows `design-system/README.md` §7–10:
  - integrations live in Settings, not on a right rail;
  - status pills appear only for exceptions;
  - names, emails and account labels go in `<bdi>`;
  - logical CSS only;
  - `dir` comes from the known language.

## What the current code tells us (verified on `main`, 2026-10-13)
1. **Notion export** (`app/api/meetings/[id]/export/notion/route.ts`, `lib/integrations/notion.ts`, 189 lines):

## Model and rules (normative)
### Connections
- A connection is one OAuth grant: `(workspace, provider, user_id?, external_account_id)`.
- **Workspace connections** (`user_id` null): `slack`, `notion`, `hubspot`. They need `integrations:manage` (admin).
- **Personal connections** (`user_id` = me): `microsoft` (calendar) and `google_drive` (Docs export). They need the new permission **`integrations:connect`** (member and up). Only the owner can configure one. Admins see its label and status and can revoke it.
- **Configured** means the provider's client ID and secret are set; otherwise its card shows "Not configured on this server" and `oauth/start` → 409 `integration_not_configured`.

### Token secrecy
- `access_token_enc` and `refresh_token_enc` use `encryptSecret(value, aad)`, where `aad = "${workspaceId}:${connectionId}:${field}"` (`v2` format). `v1` still decrypts for existing Google and bot data.
- Tokens are never selected into DTOs, logs, audit records, errors, job payloads or `progress`. Store functions select token columns only inside `lib/integrations/core/tokens.ts`.
- Errors pass through `redactIntegrationError` (strips bearer tokens, `code=`, `refresh_token`, `client_secret`, emails → `***`), capped at 500 characters. Provider response bodies are never reflected to clients.

### OAuth flow (`lib/integrations/core/oauth-state.ts`)
**Start** (`GET /api/integrations/[provider]/oauth/start?returnTo=`):
1. Authz: `integrations:manage` for workspace providers, `integrations:connect` for personal providers. The `integrationsOAuth` rate limit (10/min per user) applies.
2. Insert `integration_oauth_states(nonce = 32 bytes base64url, workspace_id, user_id, provider, code_verifier_enc, return_to, expires_at = now + 10 min)`.
3. `state = base64url(json{v:1, n, p, ws, u, exp}) + "." + HMAC-SHA256(HKDF(MEETSUM_SESSION_SECRET, "meetsum:integration-oauth-state"))`.
4. Set the cookie `meetsum_int_oauth = nonce` (httpOnly, `SameSite=Lax`, `path=/api/integrations`, 10 min, `secure` in production).
5. Redirect (302) to the provider. **PKCE S256** for `microsoft`, `google_drive` and `notion`/`hubspot` only if verified against the provider docs in the package (otherwise off). It is off for Slack, which doesn't support it for confidential clients.

**Callback** (`GET /api/integrations/[provider]/oauth/callback`, `withSession`). In order:
1. The signature is valid and `exp` has not passed.
2. Cookie nonce = state nonce = DB row, and `used_at` is null. Mark it used atomically (`update … set used_at = now() where nonce = $1 and used_at is null returning *`).
3. Session user = `state.u`, and that user is still a member of `state.ws` with the required permission (re-checked, not taken from the state).
4. Route provider = `state.p`.
5. A provider `error=` parameter → `integration_error=denied`.
6. Exchange the code (with `code_verifier` when PKCE is on). Upsert the connection, audit `integration.connection.created|updated`, clear the cookie, and redirect to `safeReturnTo(return_to)` (default `/{locale}?panel=settings&section=integrations`).

- Any failure → redirect with `?integration_error=<code>` (codes from a fixed enum). Provider text is never reflected.
- A daily sweep deletes expired states.

### Redirect URI allowlist
`redirectUri(provider) = ${MEETSUM_OAUTH_REDIRECT_BASE ?? NEXT_PUBLIC_APP_URL}/api/integrations/${provider}/oauth/callback`. It is never derived from the request. At boot, and on every start, `MEETSUM_OAUTH_REDIRECT_BASE` must parse as an origin with no path, and must be `https:` in production (else 409 `integration_not_configured`, plus a boot warning). The runbook lists exactly these URIs.

### Outbound HTTP: `providerFetch(provider, url, init)` only
- https only, with an exact host match against `PROVIDER_HOSTS` (below). There is **no env override** in production.
- `redirect: "error"`, 15 s timeout, 2 MB response cap, `user-agent: MeetSum-Integrations/1`.
- The Microsoft tenant path segment is validated (GUID, `organizations`, `common`, or `^[a-z0-9.-]+\.[a-z]{2,}$`).
- **Error mapping:** `ProviderError {kind: auth|forbidden|not_found|invalid|rate_limited|retryable|config, retryAfterMs?, providerCode?}`.
  - `kind: auth` → connection `needs_reauth`, the delivery fails without retrying, the connection creator gets an M5 notification (`integration_reauth`), and the audit records `integration.connection.needs_reauth`.
- **User-influenced URLs** never go through `providerFetch`. Webhook URLs keep `guardedWebhookFetch`. The Slack slash-command `response_url` (stretch) must match `https://hooks.slack.com/` and also goes through `guardedWebhookFetch`.
- **Fake mode (dev/e2e only):** if `MEETSUM_INTEGRATIONS_FAKE_BASE_URL` is set, `providerFetch` and the authorize URL builders rewrite every provider origin to it.
  - It must be a loopback `http://127.0.0.1:<port>` or `http://localhost:<port>`.
  - The boot check **throws** if it is set with `NODE_ENV=production`.
  - The connections API reports `fake: true` and the UI shows a "Test providers" banner.

### Token refresh (`getAccessToken(connectionId)`)
- Refresh when `expires_at − 120 s < now`, under a short refresh lease (`integration_connections.refresh_lease_until`, migration 029), so concurrent jobs can't race a rotating refresh token (Microsoft, HubSpot, and Slack with rotation enabled). The lease is taken by one conditional update (`active`, same `token_generation`, no live lease); the provider call runs with no transaction or row lock open; the new tokens are written with a compare-and-set on the generation (clearing the lease), and a failure clears the lease and records `last_error` in its own committed write. Waiters re-read until the holder finishes; an expired lease (45 s) is taken over. (Review fix: the original `select … for update` held a transaction across the provider call and rolled back the `last_error` write.)
- Always persist a newly returned refresh token.
- `invalid_grant` (or provider equivalents) → `needs_reauth`.

### Disconnect
1. Best-effort provider revoke: Slack `auth.revoke`, HubSpot `POST /oauth/v3/token/revoke` (token in the form body; review fix, was the token-in-path `DELETE /oauth/v1/refresh-tokens/{t}`), Google `oauth2.googleapis.com/revoke`. Microsoft and Notion have none.
2. Null the token columns and set `status = revoked`, `revoked_at`.
3. Dependent rules → `enabled = false`, `disabled_reason = 'connection_revoked'`.
4. Delete queued deliveries for that connection (`cancelled`).
5. Audit.

### Rules (admins only, workspace scope)
- Columns: `provider ∈ {slack, notion, hubspot, email}`, `trigger_event ∈ {meeting.completed, summary.created, action_item.created}`, `filters`, `destination`, `content`, `include_private`, `created_by_user_id`.
- **Filters** (all optional, AND-ed):
  - `roomIds[]` (meeting contexts);
  - `tagNames[]` (any match);
  - `participantDomains {mode: "any_external"|"includes"|"excludes", domains[]}`. Internal domains come from M7 `resolveInternalDomains` (member email domains plus `MEETSUM_BOT_INTERNAL_DOMAINS`);
  - `visibility[]` (default `["workspace","link"]`);
  - `languages[]`, `sources[]`, `minDurationMinutes`.
- **Content:** `{overview: true, actionItems: true, decisions: true, openQuestions: false, transcript: false, link: "app"|"existing_share"|"none"}`. A rule never creates share links, because that would flip visibility to `link`.
- **Editing:** editing a rule by another admin resets `include_private = false` and stamps the new `created_by_user_id`.

### Privacy gate (pure, `lib/integrations/core/privacy.ts`)
Runs at dispatch **and again at deliver time** after re-reading the meeting.
- `workspace`/`link` meetings → allowed (subject to filters).
- **Private** (or unknown visibility, which is treated as private) → allowed **only when the meeting owner opted in**, by either:
  - (a) `rule.include_private && rule.created_by_user_id === meeting.ownerUserId`, the owner's own rule; or
  - (b) `meeting_integration_prefs.allow_private_push = true`, set by the owner on that meeting (`set_by_user_id === ownerUserId`, re-checked).
    An opt-in given while the meeting was shared does not carry over: making a meeting private (`PATCH /api/meetings/[id]/visibility`) clears `allow_private_push` first (review fix), and an ownership change voids it through the `set_by_user_id === ownerUserId` check.
- Otherwise `skipped/private_meeting`, and the provider is never called.
- Rule creator no longer a member → `skipped/rule_owner_inactive`, and the rule is auto-disabled.
- **Manual sends:** the meeting must be visible (else 404), and private meetings need `canManageMeeting` (owner). Admins don't bypass private (the M2 rule).

### Deliveries (`integration_deliveries`, the system of record)
- They run on a separate BullMQ queue `meetsum-integrations` (as M7 does with `meetsum-bot`), so a long ASR job can't delay them. No `jobs` rows are written.
- **Idempotency keys:**
  - rule: `rule:{ruleId}:{event}:{meetingId}[:{actionItemId}]`, at most once per rule per meeting per event, so reprocessing never re-posts;
  - manual: `manual:{clientKey}`, where the client sends an `Idempotency-Key` header (uuid). The server falls back to a uuid, and a repeated key returns the same delivery.
- **Multi-call providers** (Notion appends, HubSpot engagement + tasks, email per recipient) checkpoint in `progress` (ids and hashes only), so a retry resumes and never duplicates.
- **Pending intents** (review fix): every external create writes a pending intent to `progress` on its own before the provider call and the result right after it, separately from other work (links come after). A retry that finds an intent without a result looks for our marker at the provider and adopts the object, creating it only when the marker is not found: Slack searches recent channel history for the `meetsum_delivery` message metadata marker (needs `channels:history`), Notion queries the database by the `MeetSum ID` property (or exact title and `created_time`), HubSpot searches by `hs_timestamp` and the `MeetSum ref: ms-…` marker in the body, and email treats a pending recipient as already sent (at most once).
- **Statuses:** `queued → running → sent`; `retrying` between attempts; `partial` (some sub-steps failed after the last attempt); `skipped` with a `skip_reason`; `failed`; `cancelled`.
- `external_ref` holds identifiers and URLs only (Slack `{channel, ts, permalink}`, Notion `{pageId, url}`, HubSpot `{engagementId, taskIds}`, Docs `{documentId, url}`), never content.

### External object links (re-export updates, never duplicates)
`integration_links` maps `(connection, meeting, object_kind, destination_key[, action_item_id])` → `external_id`/`url`.
- **Notion:** re-export updates the tracked page in place: PATCH properties, replace children. If the page is 404 or archived, create a new page and update the link.
- **HubSpot:** re-send PATCHes the tracked engagement and creates tasks only for action items with no link.
- **Google Docs:** re-export replaces the tracked document's body (with `?new=1` to force a new doc).
- **Slack:** a manual re-send of the same meeting to the same channel `chat.update`s the tracked message if it is under 24 h old; otherwise it posts anew.
- **Rule deliveries** use the same links, so a manual send after a rule post updates the same object.

### Isolation
- Every table has `workspace_id`. Every store function takes `workspaceId` and filters on it.
- Child IDs (rule → connection, delivery → rule, link → connection) are joined within the workspace, so other-workspace IDs → 404.
- A rule can only reference a connection in its own workspace, of the same provider and active. This is enforced with `insert … select … where c.workspace_id = $ws`, so zero rows means 404.

### Caps (enforced in the DB; exceeding one → 409)
- 20 connections and 50 rules per workspace;
- 50 rules evaluated per event;
- 50 recipients per recap;
- `MEETSUM_EMAIL_RECAP_MAX_PER_HOUR` (default 200) recap emails per workspace per rolling hour, counted from deliveries.

**A4. Dispatcher** (`integration.dispatch`, `jobId = integration.dispatch:<eventId>`):
1. Load the enabled rules for `(ws, event)`, at most 50.
2. Load `MeetingFacts` and `MeetingIntegrationPrefs` with the system repo of `ws`.
3. Apply the rule-owner check, the privacy gate, the filters and, for `email`, the recap mode (`all_meetings`, or `opt_in` requiring `prefs.email_recap = 'on'`; `prefs.email_recap = 'off'` always wins).
4. `insert … on conflict (workspace_id, idempotency_key) do nothing`, as `queued` or `skipped`.
5. Enqueue `integration.deliver` for each new queued row.

**A5. Deliver** (`integration.deliver`, `jobId = deliveryId`):
- `attempts = MEETSUM_INTEGRATION_MAX_ATTEMPTS`. Custom backoff uses `ProviderError.retryAfterMs` when present, else exponential from 30 s, capped at 1 h.
- Steps:
  1. Lock the row; terminal states are a no-op.
  2. Re-read the meeting, then re-run the privacy gate and the prefs check.
  3. `buildMeetingRecap`, then `provider.deliver`.
  4. Map errors: `auth|forbidden|invalid|not_found|config` → `UnrecoverableError` + `failed`; `rate_limited|retryable` → `retrying`.
  5. On the final attempt: `failed`, or `partial` if `progress` shows partial success.
  6. On `failed`, emit the platform event `integration.delivery.failed {deliveryId, provider, meetingId?, reason}` (no content).
- Worker concurrency `MEETSUM_INTEGRATIONS_CONCURRENCY=4`, with a limiter of 20 jobs/s.
- Provider `jobs` run as `integration.job {provider, job, workspaceId, connectionId}`. The repeatable `integration.tick` (every minute) enqueues the due per-connection jobs, with `jobId = <provider>.<job>:<connId>:<timeBucket>`.
- A daily `integration.sweep` deletes expired OAuth states and deliveries older than `MEETSUM_INTEGRATION_DELIVERY_RETENTION_DAYS` (90).

  - `audience: "members"` (the default) keeps only emails that match a **current workspace member** (exact email, not domain) **and** `canViewMeeting` for that member.
  - `audience: "attendees"` (explicitly enabled by an admin) also includes non-members, but **never for private meetings**: those always fall back to `members`.
  - Capped at `MEETSUM_EMAIL_RECAP_MAX_RECIPIENTS`.
  - The DB-checked per-workspace hourly cap applies; when it is hit → `partial` with `skip_reason=hourly_cap`, and the retry resumes the next hour.
- **One email per recipient,** so addresses are never exposed to each other. `progress.sent` holds sha256 hashes, which keeps it idempotent per recipient. The queue limiter is 5 emails/s.
- **Template** (`he`/`en`; locale from the meeting language if he/en, else the workspace default):
  - **Subject:** `סיכום פגישה: <title>` / `Meeting recap: <title>` (RFC 2047 via `encodeHeaderWord`).
  - **HTML:** `<html lang dir>`, `dir="rtl"` for Hebrew, logical CSS only (`text-align:start`), table layout for Gmail/Outlook. It contains the overview, action items (owner in `<bdi>`, due date) and decisions. All text is HTML-escaped, and emails and times are wrapped in `<bdi dir="ltr">`.
  - **Link:** members get the app link; non-members get no link unless `link = existing_share` and an active share exists.
  - **Plain-text part:** lines are RLM-prefixed for Hebrew.
  - **Footer:** why the recipient got this email (workspace name, meeting) plus an unsubscribe link.
- **Headers:**
  - `List-Unsubscribe: <https://…/api/email/unsubscribe?t=…>`;
  - `List-Unsubscribe-Post: List-Unsubscribe=One-Click` (RFC 8058);
  - `Auto-Submitted: auto-generated`;
  - `X-MeetSum-Meeting: <id>`.
  - `buildMimeMessage` passes through only these names plus `X-MeetSum-*`, each value through `sanitizeHeaderValue`. Both Gmail and SMTP senders pass them on.
- **Unsubscribe token:** `base64url(json{v:1, ws, e, iat})` + HMAC (`HKDF(MEETSUM_SESSION_SECRET, "meetsum:email-unsubscribe")`), no expiry, verified timing-safe.
- **Unsubscribe route:**
  - `GET` → 302 to `/{locale}/unsubscribe?t=`, a confirmation page with a POST button, so link scanners never mutate state;
  - `POST` (form or one-click) → upsert the unsubscribe, audit `email.unsubscribed`, return 200;
  - rate-limited with `publicAccess`; an invalid token → 400 with no detail.
- **Audit:** `email.recap.sent {meetingId, sent, skipped, failed}`.

## Security checks (each needs a test; reviewers verify)
1. **OAuth.** State is HMAC-signed, single-use (atomic `used_at`), cookie-bound, 10-minute expiry, and bound to workspace + user + provider. Membership and permission are re-checked at the callback. PKCE S256 is used wherever the provider supports it. The redirect URI comes only from `MEETSUM_OAUTH_REDIRECT_BASE`, never request headers. `returnTo` goes through `safeReturnTo`. Errors use a fixed code enum.
2. **Token secrecy.** AES-GCM with AAD `ws:conn:field`. A ciphertext moved between rows fails. Tokens never appear in DTOs, responses, logs, audit, `last_error`, `progress`, `external_ref`, job payloads or the fake-server request log. This is enforced by the token-leak test.
3. **Refresh.** Row-locked refresh; rotated refresh tokens are persisted; `needs_reauth` on `invalid_grant`, with a notification; disconnect wipes tokens and best-effort revokes.
4. **Outbound HTTP.** Provider calls go only to the exact-host allowlist, https, `redirect: "error"`, with time and size caps. User-influenced URLs (webhooks, Slack `response_url`) go through `guardedWebhookFetch`, which blocks private, metadata and CGNAT ranges and DNS rebinding. Fake mode is impossible in production (boot throws).
5. **Workspace scoping.** Every query is keyed by `workspace_id`; cross-workspace ids → 404; rules can only reference same-workspace connections. Checked by the isolation test.
6. **Private meetings.** Never pushed unless the owner opted in (their own rule with `include_private`, or the per-meeting `allow_private_push` set by the owner). Re-checked at deliver time. Manual sends need owner/manage. Email recap for private meetings goes to members who can view it only. Checked by the private-exfiltration test (provider HTTP never called).
7. **Audit without content.** `integration.connection.*`, `integration.rule.*`, `integration.delivery.*`, `integration.manual_send`, `integration.meeting_prefs.updated`, `meeting.export.*`, `email.*`: ids, provider, status and counts only.
8. **Rate limits and idempotency.** Rate limits on OAuth start, writes, manual send, exports, test-fire and unsubscribe. DB caps on connections, rules, recipients and emails per hour. Idempotency keys on every push (rule keys plus the client `Idempotency-Key` for manual sends). External-object links prevent duplicates on re-export.
9. **Injection.** Slack mrkdwn escaping (no `<!channel>`, mentions or links from content). HubSpot and email HTML are escaped. Email headers are allowlisted and sanitized (no CRLF). Notion and Docs get text only, never markup.
10. **Webhooks.** v2 timestamped signature (replay window). The secret is shown once and stored encrypted (unchanged). Test-fire to an ad-hoc URL uses a throwaway secret (unchanged). Private payloads are minimal for every event.
11. **Public endpoints.** Unsubscribe: signed token, GET never mutates. Slack commands (stretch): v0 signature, ±5 min, membership by email. Graph notifications (stretch): clientState hash, timing-safe; only enqueues a sync.

## Defaults and open questions (flag in the PR)
- **`summary.ready` vs `summary.created`:** the catalog keeps the existing name `summary.created` in v1 and v2 so existing Zaps don't break. Rename only if the owner wants it (it would be v2-only, with v1 unchanged).
- **Slack `chat:write.public`** is requested so the app can post without an invite; remove it via `SLACK_SCOPES`. The slash command is stretch, behind `SLACK_COMMANDS_ENABLED`.
- **Email recap audience:** members only by default; "attendees" (external people) needs an explicit admin toggle and never applies to private meetings. Off unless the workspace creates the rule.
- **Private opt-in has two owner paths** (the owner's own rule with `include_private`, or the per-meeting toggle). Admins can never opt a meeting in for someone else.
- **Re-export semantics:** Notion and Docs update in place (in Notion, old blocks are archived, so page history keeps them); Slack updates the message only within 24 h. Rule deliveries stay at most once per rule, meeting and event, so reprocessing never re-posts automatically.
- **Notion version** is pinned to `2022-06-28`; the data-source API migration is deferred. Notion RTL is verified empirically on the first live run.
- **Microsoft scope** drops `OnlineMeetings.Read` (`joinUrl` comes with `Calendars.Read`). Calendar push is stretch only.
- **HubSpot** scopes and association type IDs, plus the Notion and Graph delta details, must be verified against current provider docs and fixtures before merge.
- **Webhook v2** is opt-in for existing subscriptions; v1 payloads are frozen. Both signature headers are sent.
- **One encryption key** is shared by Google and integration tokens (AAD separates rows); key rotation is deferred to M10.
- **Out of scope:** Zapier app listing, ICS export, Salesforce/Pipedrive/Jira/Asana, Slack interactivity beyond the stretch command, PDF Hebrew shaping (M9), RealizeOS private-meeting policy review (M10).
- **External inputs needed:** the apps in "External apps checklist". Until they exist, M8 merges on fixture tests and the fake-provider e2e, and live runs are listed as pending in STATUS.
