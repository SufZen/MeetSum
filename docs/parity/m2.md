# M2 — Multi-user workspaces: implementation spec

Base branch `parity/m2-workspaces` (stacked on `parity/m1-pipeline`; migrations 015–017 present). Four parallel packages A/B/C/D, strictly disjoint file ownership. Step 0 (orchestrator) commits migrations + contracts with *compat* implementations so every branch stays green; an Integration step removes shims and adds global leak tests.

Notes vs. brief: `shareActionsByDefault` is already live (share route) → 8 dead settings, not 9. `api_keys.scopes jsonb default '[]'` already exists (001) → reused.

## Model & rules (normative)
- Workspace = tenant. User = Google identity (lowercased email). Membership (workspace, user, role).
- Roles `owner > admin > member > viewer`. API key scopes `admin ⊃ write ⊃ read` → roles admin/member/viewer (never owner).
- `ROLE_PERMISSIONS` (`lib/auth/authz.ts`):
  - viewer: `workspace:read`, `meeting:read`, `jobs:read`
  - member: + `meeting:write`, `meeting:create`, `contexts:write`, `jobs:write`
  - admin: + `settings:write`, `members:manage`, `api_keys:manage`, `webhooks:manage`, `integrations:manage`, `storage:manage`, `audit:read`, `ops:read`
  - owner: + `owners:manage`, `workspace:delete`
- Meeting visibility `private | workspace | link` (+ `owner_user_id`): `workspace` = all members; `link` = workspace + active share token holders; `private` = owner + users whose email matches a `meeting_participants.email` of that meeting. Admins do NOT bypass private (deliberate). API-key principal: workspace|link + private owned by `api_keys.created_by_user_id`. System scope (worker, signed webhooks): workspace filter only.
- Meeting actions: read = visible; write = visible ∧ role ≥ member; share/visibility/delete = visible ∧ (owner = me ∨ role ≥ admin; API key needs `admin`).
- Invisible / other-workspace → **404** (no existence leak). Missing role → 403 `{error:"Forbidden", permission}`. No credentials → 401. Bad bearer → 401 without cookie fallback. Session non-GET requests pass an Origin check (Origin host = request host or `NEXT_PUBLIC_APP_URL` host).
- New meetings: `workspace_id` = principal's; `owner_user_id` = user (or key creator); `visibility` = workspace setting `defaultMeetingVisibility` (default `workspace`).
- Creating a share link sets visibility `link` (UI warns if private). Leaving `link` revokes active shares in the same tx.
- `workspace_id` columns have **no DB default** (fail loudly).
- `workspaces.google_subject` (DWD identity) settable only by bootstrap (env subject) or by an owner to **their own email**.
- Allowlist (`MEETSUM_ALLOWED_EMAILS` → `GOOGLE_WORKSPACE_SUBJECT`) becomes bootstrap-only: listed emails always get a membership in `ws_default`. No self-signup.
